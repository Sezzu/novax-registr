# NovaX — New era: Telegram-бот

Python 3.12, aiogram 3.31.0, асинхронный SQLAlchemy, SQLite и Alembic. `requirements.txt` задаёт прямые зависимости, `requirements.lock` фиксирует полный набор версий, прошедший тесты; Docker использует lock-файл. «Королевские Битвы» — формат ивентов внутри NovaX. Интеграции с Paper нет; поддерживаемая версия по умолчанию — Java 1.21.4. Дополнительные версии администратор указывает только если сервер их действительно поддерживает.

## Быстрый запуск через Docker

Создайте бота у @BotFather. В папке проекта:

```powershell
Copy-Item .env.example .env
notepad .env
docker compose up -d --build
docker compose logs -f bot
```

Заполните BOT_TOKEN, BOT_USERNAME (без @), ADMIN_IDS (числовые Telegram ID через запятую), CHANNEL_ID (например @novax_channel или числовой -100… для приватного канала), DEFAULT_TIMEZONE (например Europe/Moscow). Добавьте бота администратором канала с правом публикации. Фактический username проверяется через Telegram и используется штатным генератором deep link aiogram. Токен храните только в `.env`; не включайте в архив или Git. Docker читает `.env` через `env_file`; образ его не содержит.

SQLite хранится в именованном томе `novax_data`. Не запускайте несколько экземпляров polling с одним токеном. Остановка: `docker compose down`. Команда `docker compose down -v` удалит базу, не используйте её для обычной остановки.

## Локальный запуск (Windows, Python 3.12)

Можно запустить двойным щелчком `start.bat`. Он создаёт `.venv`, устанавливает закреплённые зависимости, проверяет `.env`, применяет миграции и запускает бот. При первом запуске введите свой числовой Telegram ID для ADMIN_IDS. Если токен ещё не записан, батник запросит его скрытым вводом. CHANNEL_ID можно указать позже в `.env`. Остановка — Ctrl+C или закрытие окна. При ошибке окно остаётся открытым, чтобы прочитать сообщение.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m app.main
```

Linux/macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp .env.example .env
# Заполните .env в редакторе
.venv/bin/alembic upgrade head
.venv/bin/python -m app.main
```

Все команды выполняются из папки, содержащей README. Сначала обязательно применяйте миграции. Они создают папку `data` при использовании SQLite. Запуск Docker применяет миграции автоматически.

## Первое событие

Для хостинга укажите `DEFAULT_TIMEZONE=Europe/Moscow`. Переменные в панели хостинга имеют приоритет над `.env`: если там записано `Moscow`, измените значение в панели и перезапустите приложение. Обновлённый валидатор также принимает Moscow/Москва/МСК/MSK и сохраняет Europe/Moscow. Неизвестный пояс выдаёт понятную ошибку настройки. Среда проекта — Python 3.12, Dockerfile уже использует python:3.12-slim.

Миграция 001 создаёт событие ID 1 на **11 октября 2026 года**. Миграция 002 добавляет обложку, расписание регистрации и сведения о публикации, сохраняя все старые данные. В новой базе регистрация закрыта. В текущей локальной базе по поручению владельца регистрация настроена на открытие **8 октября 2026 в 22:00 Europe/Moscow**, а время самой битвы пока не задано. Напоминания ждут настройки времени. В личном чате администратора можно изменить детали кнопками через `/edit_event`, либо командами:

```text
/set 1 time 18:00
/set 1 timezone Europe/Moscow
/set 1 description Королевская Битва на сервере NovaX — New era. Приходи с командой или играй один.
/set 1 rules Здесь вставьте утверждённые правила вашего ивента.
/open 1
/set 1 cover_image assets/royal-battle.png
/publish_event
```

18:00 — пример, замените на утверждённое время. Правила задаёт администратор: бот не придумывает правила сервера. До их настройки кнопка правил показывает понятное сообщение об уточнении деталей. На экране появится предпросмотр с кнопками «✅ Опубликовать», «✏️ Изменить», «❌ Отмена». Публикация происходит только после подтверждения. В Telegram нельзя задать физический размер inline-кнопки: кнопка участия занимает отдельную строку.

Для отложенного открытия: `/set 1 registration_opens_at 2026-10-08T22:00`, затем `/open 1`. Часовой пояс берётся из события. До указанного момента кнопка участия сообщает дату открытия. При неизвестном времени битвы разрешены регистрации на будущую дату; в сам день события без уточнённого времени регистрация закрывается. Закрытие `/close` имеет приоритет над расписанием. После изменения времени опубликованный пост автоматически обновится.

## Участник

1. Кнопка «⚔️ Буду участвовать» в канале открывает `https://t.me/BOT_USERNAME?start=event_1`.
2. Сразу после Start появляется конкретный ивент с обратным отсчётом, датой, временем и поясом, IP, версиями и числом активных участников. Общего меню или списка команд при deep link нет. До настройки времени отображается «Время уточняется администратором».
3. «⚔️ Буду участвовать» → ник `[A-Za-z0-9_]{3,16}` → «Как ты будешь играть?» → «Напомнить перед началом?».
4. Подтверждение содержит только собственный ник. Кнопки позволяют изменить ответы, отменить участие, открыть правила и агрегированную статистику без ников.
5. Повторное нажатие показывает существующую регистрацию. Изменение заменяет ответы в той же записи. Отмена выключает напоминания и исключает участника из активной статистики. Можно зарегистрироваться снова, пока регистрация открыта и событие не началось.

Ссылки: `event_ID` — основной payload; для уже опубликованного события источник определяется как channel, для неопубликованного — unknown. Старые ссылки `event_ID_channel`, `event_ID_tiktok`, `event_ID_youtube`, `event_ID_friend` поддерживаются. Сохраняется первый источник для уникальной пары пользователь/событие. Неизвестный или неверный аргумент `/start` не вызывает ошибку. Метки источников не являются доказательством происхождения трафика — пользователь может изменить ссылку.

Команды: `/start`, `/events`, `/my_registration`, `/privacy`, `/delete_me`, `/abort`. `/delete_me` сразу удаляет пользователя, регистрации, источники, доставки, собственные записи административного аудита и текущий опрос. Затем пользователь может начать заново. Статистика после удаления пересчитывается. Данные из ранее экспортированных файлов должны удаляться администратором отдельно.

Опрос и предпросмотры хранятся в памяти: после перезапуска незавершённый опрос нужно начать снова. Готовые регистрации сохраняются. Бот работает только в личных чатах, чтобы ответы не попадали в группы.

## Администратор

Доступ к командам и подтверждениям проверяется по Telegram ID из ADMIN_IDS, а не по username. `/admin` выводит справку.

| Команда | Действие |
|---|---|
| `/create 2026-10-11 \| 18:00 \| Europe/Moscow \| Описание` | Создать закрытое событие, вернуть ID |
| `/set ID поле значение` | Изменить date/time/timezone/description/ip/versions/rules |
| `/open ID`, `/close ID` | Открыть или закрыть регистрацию |
| `/stats ID` | Полная статистика |
| `/export ID` | CSV активных регистраций в личный чат администратора |
| `/publish ID` | Предпросмотр поста и публикация в CHANNEL_ID после подтверждения |
| `/publish_event [ID]` | Предпросмотр ближайшего события (или выбранного ID), публикация с обложкой и кнопкой |
| `/edit_event [ID]` | Изменение даты, времени, описания, IP, версий, правил, обложки, открытия регистрации кнопками |
| `/channel_test [ID]` | Отправить тестовый пост с кнопкой в канал, вернуть message_id |
| `/broadcast ID текст` | Предпросмотр рассылки активным участникам и подтверждение |
| `/abort` | Сбросить опрос или предпросмотр |

Дата: YYYY-MM-DD; время: HH:MM; пояс: IANA (например Europe/Moscow). Несуществующее и двусмысленное местное время при переводе часов отклоняется. Открытие требует будущей даты и описания; точное время можно уточнить позже. Редактирование даты в прошлое автоматически закрывает регистрацию. Рассылка ограничена 3000 символами, описание 1800, правила 3000; HTML из введённых данных экранируется. CSV содержит персональные данные и отправляется только администратору. Допустимые ники исключают формулы CSV.

### Публикация и права канала

При запуске бот вызывает getChat и getChatMember, проверяет тип channel, роль администратора и can_post_messages. Ошибка прав отправляется администраторам в личный чат понятным сообщением. /channel_test выполняет ту же проверку. Бот не может сам назначить себе права — это делает владелец канала в Telegram.

Пост отправляется прямо в канал от имени канала с HTML-подписью и InlineKeyboardMarkup. Обложка события: Telegram file_id, URL или изображение в assets/. Для загрузки фото администратором проверяется соотношение сторон 16:9. Если Telegram явно отклонил изображение или локальный файл отсутствует, используется текстовая версия. При неопределённой сетевой ошибке повторная отправка запрещена, поскольку фотография могла уже доставиться.

До запроса Telegram событие атомарно получает статус publishing; только один конкурентный запрос может его получить. После отправки сохраняются channel_message_id, числовой channel_chat_id, тип поста и время обновления. published/publishing/uncertain не публикуются снова даже после перезапуска. Явный отказ Telegram переводит событие в failed и разрешает повторить предпросмотр. Если процесс остановится после отправки до сохранения ID, повтор заблокирован; проверьте канал перед ручным восстановлением записи. Эта граница защищает от дублей, но не гарантирует доставку.

Счётчик participant_count хранится в events и пересчитывается в той же транзакции при подтверждении, отмене и /delete_me. Планировщик обновляет текст поста или подпись фото через editMessageText/editMessageCaption не чаще раза в 300 секунд. Редактирование метаданных события также обновляет подпись. Если текст не изменился, запрос не отправляется. Тип обложки в уже опубликованном посте автоматически не заменяется; изменение обложки действует для будущих публикаций. CHANNEL_ID меняется для новых постов, ранее сохранённые редактируются в исходном канале.

Предпросмотр действует 10 минут и привязан к личному состоянию администратора. Подтверждение удаляет его до отправки; повторное нажатие не повторит отправку. Новый предпросмотр заменяет старый. После перезапуска подтверждение недействительно. Перед фактической отправкой проверяется существование события. Если данные события изменились после предпросмотра анонса, бот отклонит публикацию: сформируйте новый предпросмотр.

`/stats`: уникальные открывшие ссылку события, уникальные начавшие опрос, уникальные когда-либо завершившие регистрацию, активные участники, число переходов в отменённое состояние, согласившиеся среди активных, три командных статуса, первые источники. Конверсия — доля открывших, которые когда-либо завершили регистрацию; отменённые остаются в историческом завершении, но не в активном счётчике. Повторные клики не увеличивают воронку.

## Напоминания и ошибки Telegram

Планировщик проверяет базу каждые 20 секунд. Напоминания получают только активные регистрации с согласием:

- Утром в локальный день события в MORNING_HOUR (по умолчанию 09:00); окно догоняющей отправки — 1 час и только до начала события.
- За 2 часа; окно отправки — 10 минут.
- За 15 минут; окно — до начала события, сообщение содержит IP и кнопку «🚀 Захожу на сервер».

Кнопка входа подтверждает намерение в чате и **не отмечает фактическую явку**. Закрытие регистрации не отменяет событие и не отключает напоминания уже зарегистрированным.

Для каждого типа стоит уникальное ограничение `(event_id, user_id, kind)`. Перед Telegram-запросом база фиксирует `claimed`, после результата — `sent` или `failed`. После перезапуска все три статуса блокируют повторную отправку. Это **at-most-once**, а не гарантия доставки: при остановке между записью и запросом напоминание может быть пропущено. При сетевой ошибке результат Telegram неизвестен, повторного запроса нет. Telegram не предоставляет ключ идемпотентности sendMessage, поэтому одновременно гарантировать доставку и отсутствие дублей невозможно. При 429 бот ждёт retry_after; блокировка бота/неверный чат обрабатываются без падения. Не меняйте записи доставок вручную, если не готовы к повторным сообщениям. Изменение времени события не сбрасывает уже отправленные типы напоминаний.

Ограничитель входящих действий: минимум 0,7 секунды между действиями пользователя. Сериализация обновлений одного пользователя защищает от двойного подтверждения. Рассылка отправляет не быстрее 20 сообщений в секунду и учитывает ограничения Telegram. Логи — JSON, без текстов сообщений, ID участников, ников и токена; записывается только тип ошибки. Не включайте HTTP debug-логи с токеном.

## Схема и архитектура

```text
app/
  configuration.py   — .env, секрет токена, настройки
  texts.py           — русские тексты и шаблоны
  main.py            — polling и жизненный цикл планировщика
  handlers/          — пользовательские и административные действия, middleware
  keyboards/         — inline-кнопки
  services/          — регистрации, события, доставки Telegram, напоминания
  database/          — ORM-модели и async-подключение
migrations/          — Alembic; 001_initial создаёт схему и ближайшее событие
tests/               — автоматические тесты
```

| Таблица | Поля и ограничения |
|---|---|
| users | Telegram ID; имя/телефон/возраст не сохраняются |
| events | ID, дата, nullable время, IANA-пояс, описание, IP, версии, правила, opened |
| registrations | ID, event_id, user_id, ник, команда, согласие, active, completed, cancellations; UNIQUE(event_id,user_id) |
| referral_sources | ID, event_id, user_id, source; UNIQUE(event_id,user_id) |
| reminder_deliveries | ID, event_id, user_id, kind, status; UNIQUE(event_id,user_id,kind) |
| admin_actions | ID, admin_id, action, event_id, Unix timestamp; без содержимого рассылок |

Связи событий и пользователей с регистрациями/источниками/доставками — внешние ключи с каскадным удалением. SQLite foreign_keys включён. Время вычисляется в UTC, конфигурация события хранится в локальной дате и поясе. Ник публично не показывается; публичного списка ников в MVP нет, следовательно отдельное согласие на публикацию не собирается.

Дополнительные поля events после 002: cover_image, registration_opens_at (Unix timestamp), participant_count, channel_message_id, channel_chat_id, publication_status, channel_is_photo, channel_last_edit, channel_content_hash. Существующие регистрации сохраняются; миграция заполняет participant_count из активных записей.

## Миграции и PostgreSQL

```powershell
.\.venv\Scripts\alembic.exe current
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\alembic.exe revision --autogenerate -m "change schema"
```

Просмотрите сгенерированную миграцию перед применением. Начальная миграция хранит явную схему, не создаёт её из текущих ORM-моделей. Откат `alembic downgrade base` удаляет все таблицы и данные.

Для новой PostgreSQL-базы замените DATABASE_URL на `postgresql+asyncpg://user:password@host:5432/novax` и выполните `alembic upgrade head`. asyncpg включён в зависимости, ORM и миграция не привязаны к SQLite. Смена URL **не переносит существующие данные**: для переноса остановите бот, выгрузите и загрузите шесть таблиц в порядке внешних ключей, восстановите последовательности ID и проверьте счётчики. PostgreSQL не требуется для запуска MVP и не проверялся против живого сервера в этой поставке.

Для резервной копии SQLite остановите контейнер, скопируйте `/app/data/novax.db` из тома, затем запустите бот. Сохраняйте резервные копии и CSV с ограниченным доступом, с установленным сроком хранения.

## Будущая интеграция Paper

Сервисы не зависят от Telegram handlers: новый защищённый API сможет вызывать тот же слой данных и регистрации. API в MVP отсутствует, наружу порты не открыты. Для плагина Paper потребуется отдельная модель фактической явки, авторизация запросов, защита от replay и привязка Minecraft UUID. Telegram-кнопка не заменяет эти сведения. Администратор сейчас отмечает явку вне бота; таблица регистраций хранит намерение участвовать.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q app migrations
```

Тесты используют временную SQLite и имитацию Telegram API: повторная и одновременная регистрация, изменение ответов, отмена и возврат, статистика/источники, удаление данных, неверные ники, закрытая/отложенная регистрация, защита административных команд, напоминания, deep link, HTML, права канала, текст/фото и fallback, конкурирующая публикация и повтор после перезапуска, сохранение ID, обновление счётчика с интервалом пять минут и сохранность старых регистраций после миграции. Для реальной публикации и рассылок нужен заполненный .env и права бота в канале.


### База данных на хостинге

При запуске `python -m app.main` бот автоматически применяет миграции до обработки сообщений. Загружайте весь проект с папкой `migrations` и `alembic.ini`. Существующие регистрации сохраняются.

Для старой версии команда запуска из корня проекта: `python -m alembic upgrade head && python -m app.main`. Каталог из DATABASE_URL должен находиться на постоянном диске и быть доступен для записи. Не удаляйте существующую базу.

Лог database_startup_failed содержит database_reason: missing_table/missing_column — отсутствует схема; cannot_open_database/permission_denied — путь или права; read_only_database — запрет записи; database_locked — база занята. Логи не содержат запросов и данных участников.


### Inline-панель администратора

Откройте /start → «Управление сервером» или /admin. Выберите событие: настройки, предпросмотр публикации, открытие/закрытие регистрации, статистика, экспорт участников и рассылка доступны кнопками. Создание нового события также начинается кнопкой. Для описания, правил, даты, времени, IP и версий бот запрашивает только значение выбранного поля — команды писать не нужно. Часовой пояс Москва/UTC и удаление обложки выбираются кнопками. Фото можно загрузить сообщением. Токен и параметры подключения к базе остаются в настройках хостинга.

Если лог содержит telegram_polling_conflict, остановите другие экземпляры этого бота: локальный запуск, дублирующий сервис или второй контейнер. Должен работать один процесс polling на один токен. При telegram_network_failed проверьте доступ хостинга к api.telegram.org. При запуске бот снимает webhook без удаления ожидающих сообщений.
